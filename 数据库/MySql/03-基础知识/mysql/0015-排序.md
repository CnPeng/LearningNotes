# 1. 0015-排序

## 1.1. 技巧和知识点


在MySQL中，`ORDER BY`子句用于对查询结果进行排序，以下是一些关于`ORDER BY`排序的技巧和知识点：

### 1.1.1. **基本用法**：

使用`ORDER BY column ASC`或`ORDER BY column DESC`来对`column`字段进行升序或降序排列，默认是升序排列（ASC）。

### 1.1.2. **多字段排序**：

可以同时对多个字段进行排序，例如：

```sql
ORDER BY column1 ASC, column2 DESC
```

MySQL会首先根据`column1`进行排序，当`column1`值相同时，再按照`column2`进行排序。

### 1.1.3. **索引优化**：

`ORDER BY`可以利用索引进行排序，尤其是当排序字段是索引的一部分时，能够大大提高查询效率。

若排序字段不是索引的最左前缀或者跨过了索引的连续部分，则 MySQL 可能无法利用索引进行排序，而是采用临时文件排序（Filesort）。

### 1.1.4. **NULL值处理**：

在排序时，`NULL`值通常会被视为最小值（升序时）或最大值（降序时）。

若要将`NULL`值放在最前或最后，可以使用`IS NULL`或`COALESCE`函数：

```sql
ORDER BY column IS NULL, column ASC
```

### 1.1.5. **排序算法**：

MySQL 在内部使用不同的排序算法，如：快速排序、归并排序等，具体算法取决于查询优化器的选择。

当无法使用索引排序时，MySQL 可能会使用临时表或内存排序，如果数据量太大则可能溢出至磁盘，这会导致性能下降。

### 1.1.6. **索引覆盖排序**：

如果查询的排序字段都在索引中，并且查询的所有列也都被索引覆盖（即索引包含了查询所需的所有列），则称为“索引覆盖排序”，效率非常高。

### 1.1.7. **排序与LIMIT结合**：

当`ORDER BY`与`LIMIT`配合使用时，特别是在分页查询时，合理的索引设计对提升性能至关重要。

### 1.1.8. **避免隐式类型转换**：

如果排序字段涉及到隐式类型转换，可能导致无法利用索引，所以在编写查询时要确保排序字段的数据类型与索引一致。

### 1.1.9. **全文索引排序**：

对于全文索引，可以使用`MATCH()`函数配合`AGAINST()`进行排序，但其排序规则不同于常规的字符串排序。

### 1.1.10. **子查询和JOIN排序**：

在含有子查询或 JOIN 的查询语句中，确保`ORDER BY`子句在合适的层级生效，以达到预期的排序结果。

总之，优化`ORDER BY`排序的关键在于理解查询计划和索引设计，尽可能使 MySQL 能够利用索引来完成排序，从而提高查询性能。同时，也要关注查询的实际需求，合理设计排序规则，适应业务逻辑的要求。

## 1.2. 借助 convert

下面的代码是使用 golang + Gorm 中的排序语句，借助了 `convert` 函数。

```go
// 先按照 building_name 字段能够转换为数字的结果进行升序排序，如果转换失败，则按照 GBK 编码格式下的字符串进行升序排序
db = db.Order("convert(building_name ,SIGNED) asc, convert(building_name using gbk) asc")
```
