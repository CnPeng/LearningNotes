# 1. 001-static和单例

## 1.1. static和单例的区别

在Java中，static和单例都是用来控制对象创建和使用的概念，但是它们有一些关键的区别：

* static关键字用于定义静态变量和方法，它们属于类而不是实例，可以通过类名直接访问。单例则是一个设计模式，用于确保一个类只有一个实例，并提供全局访问点。

* 静态成员可以被多个实例所共享，而单例只有一个实例存在，并且该实例在整个应用程序生命周期内都存在。

* 单例实现需要使用特定的设计模式，如双重校验锁或枚举类型等，而静态变量和方法则可以直接在类中声明和使用。

* 单例在多线程环境下需要考虑并发性和同步性，而静态成员则不涉及这些问题。


## 1.2. static的作用和实现方式

static和单例都是Java中常用的编程概念，但它们的作用和实现方式有所不同。

### 1.2.1. static

static关键字用于定义类的静态变量或静态方法，它们属于类而不是实例对象。静态变量在类被加载时就会创建，而不是在实例化对象时。静态方法可以直接通过类名调用，不需要创建实例对象。静态变量和静态方法的生命周期与类的生命周期相同。

### 1.2.2. 单例

单例是一种设计模式，用于保证一个类只有一个实例对象，并提供全局访问点。单例模式常用于需要限制某些资源的使用，比如数据库连接池、线程池等场景。
单例模式的实现方式有多种，其中最常见的是饿汉式和懒汉式。饿汉式在类加载时就创建了实例对象，而懒汉式在第一次调用时才创建实例对象。
区别：

* static 用于定义静态变量和静态方法，而单例用于保证一个类只有一个实例对象。
* static 变量和方法属于类，而单例实例对象属于类的实例。
* static 变量和方法的生命周期与类相同，而单例实例对象的生命周期与应用程序相同。
* static 变量和方法可以直接通过类名调用，而单例实例对象需要通过 getInstance() 等方法获取。



## 1.3. static和单例的使用场景

Java中static和单例都是重要的编程概念，它们应用于不同的场景。

### 1.3.1. static的使用场景

* 当一个变量或方法需要被所有实例共享时，可以使用 static 关键字定义它。比如，一个计数器变量，需要在每个实例中递增，可以定义为静态变量。
* 当一个方法不依赖于实例对象的状态，只需要根据输入参数进行计算时，可以定义为静态方法。比如，Math 类中的 abs() 方法。

### 1.3.2. 单例的使用场景

* 当需要限制某个类的实例只能有一个，并提供全局访问点时，可以使用单例模式。比如，数据库连接池、日志记录器等。
* 当一个类的实例对象的创建和销毁需要进行严格控制时，可以使用单例模式。比如，线程池、缓存管理器等。

需要注意的是，单例模式在多线程环境下需要进行线程安全的设计，避免多个线程同时创建实例对象。可以使用双重检查锁定、静态内部类等方式实现线程安全的单例模式。


## 1.4. 优先使用单例还是 static

Java中使用单例还是static，取决于具体的业务场景和需求。

* 如果需要限制一个类的实例只能有一个，并提供全局访问点时，可以使用单例模式。比如，数据库连接池、日志记录器等。
* 如果一个变量或方法需要被所有实例共享时，可以使用 static 关键字定义它。比如，一个计数器变量，需要在每个实例中递增，可以定义为静态变量。
* 如果一个方法**不依赖于实例对象的状态**，只需要根据输入参数进行计算时，可以定义为静态方法。比如，Math 类中的 abs() 方法。

需要注意的是，单例模式在多线程环境下需要进行线程安全的设计，避免多个线程同时创建实例对象。可以使用双重检查锁定、静态内部类等方式实现线程安全的单例模式。

总的来说，单例模式和static都是Java中常用的编程概念，应该根据具体的业务需求来选择使用哪种方式。
