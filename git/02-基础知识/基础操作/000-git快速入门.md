# 1. 000-git快速入门

虽然各个代码编辑器都自带了 git 图形化工具，或者支持图形化插件，但依旧建议了解并优先使用 git 命令完成相关操作。

---

## 1.1. Git 是什么？

Git 是一个**代码版本管理工具**。你可以把它想象成一个"时光机"：

- 它能记录你项目的每一次修改，随时可以回退到之前的任何一个版本
- 它支持多人协作开发，每个人可以在自己的分支上工作，最后再合并在一起
- 它能把代码同步到远程服务器（如 GitHub、GitLab），实现备份和团队协作

### 1.1.1. Git 的核心工作流程

```
工作区(你正在编辑的文件) → 暂存区(准备提交的文件) → 本地仓库(正式存档) → 远程仓库(云端备份)
         ↑                        ↑                        ↑
       你改代码                git add                 git commit
```

简单说就是三步走：**改代码 → 暂存 → 提交**。

## 1.2. 安装与首次配置

### 1.2.1. 安装 Git

#### 1.2.1.1. Windows

- 访问 https://git-scm.com/downloads 下载安装包
- 一路下一步安装即可
- 安装完成后打开 **Git Bash**（不是普通的 CMD）来使用命令

#### 1.2.1.2. macOS

- 方法一：终端执行 `brew install git`
- 方法二：安装 Xcode Command Line Tools：`xcode-select --install`

#### 1.2.1.3. Linux（Ubuntu/Debian）

```bash
sudo apt install -y git
```

### 1.2.2. 验证安装

```bash
git --version
```

看到类似 `git version 2.43.0` 的输出就说明安装成功了。

### 1.2.3. 首次配置（全局配置一次即可）

Git 需要知道你是谁，这样每次提交都会带上你的名字和邮箱：

```bash
# 设置你的用户名（可以随便填，但建议用真实名字）
git config --global user.name "你的名字"

# 设置你的邮箱（建议用注册 GitHub 时用的邮箱）
git config --global user.email "your@email.com"

# 查看已配置的信息
git config --list
```

> **提示**：`--global` 表示全局配置，只对当前用户生效，所有项目都会使用这些配置。

## 1.3. 核心概念详解（必看）

在学命令之前，先理解 Git 的几个关键概念，后面学命令会轻松很多。

### 1.3.1. 三个区域

Git 管理文件涉及三个区域：

| 区域 | 通俗解释 | 对应命令 |
|------|---------|---------|
| **工作区（Working Directory）** | 你电脑上正在编辑的项目文件夹 | 你直接用编辑器改文件 |
| **暂存区（Staging Area）** | 一个"待发货清单"，列出你这次想提交哪些改动 | `git add` |
| **本地仓库（Local Repository）** | 正式的"存档柜"，保存你所有提交的历史记录 | `git commit` |

**工作流程：** 你在工作区改文件 → 用 `git add` 把改动放进暂存区 → 用 `git commit` 把暂存区的内容正式存档到本地仓库。

### 1.3.2. 分支（Branch）

分支就像平行宇宙：

- **主分支（main/master）**：通常是稳定可用的正式版本
- **功能分支（feature branch）**：你在上面开发新功能，不影响主分支

**为什么要用分支？** 想象你在写论文，主分支是最终版。你想加一章新内容，如果直接在主分支上改，改坏了就麻烦了。有了分支，你可以在"新章节"分支上随便改，改好了再合并到主分支，改坏了就删掉分支重来。

### 1.3.3. 远程仓库（Remote）

远程仓库就是托管在网上的代码仓库（如 GitHub、GitLab、Gitee）。它的作用：

- **备份**：防止电脑坏了代码丢失
- **协作**：多人可以同时在一个项目上工作
- **同步**：在一台电脑推送代码，另一台电脑拉取代码

## 1.4. 初始化仓库与克隆

### 1.4.1. 新建一个本地仓库

如果你在自己的电脑上从头开始一个新项目，可按如下方式初始化 git :

```bash
# 1. 使用 mkdir 命令创建一个名称为 my-project 的项目文件夹
mkdir my-project
# 1-1. 使用 cd 命令切换到新建的文件夹目录下
cd my-project

# 2. 把这个文件夹初始化为 Git 仓库
git init
```

执行 `git init` 后，文件夹里会多出一个隐藏的 `.git` 目录，这就是 Git 的"数据库"，记录着所有的版本历史。**千万不要手动删除或修改这个目录。**

### 1.4.2. 从远程仓库克隆

如果项目已经在 GitHub/GitLab 等 git 仓库中存在了，你需要参与协作开发，则可以把它克隆到本地：

```bash
# 克隆远程仓库到本地
git clone https://github.com/username/repo.git

# 进入项目目录
cd repo
```

`git clone` 会自动完成三件事：下载代码、初始化本地仓库、建立与远程仓库的连接。

## 1.5. 日常操作：查看状态与提交

### 1.5.1. 查看文件状态

```bash
# 查看当前所有文件的状态（哪些被修改了、哪些是新文件）
git status
```

输出示例：

```
On branch main
Changes not staged for commit:
  modified:   main.py

Untracked files:
  new_file.txt

no changes added to commit (use "git add" and/or "git commit -a")
```

- **modified**：已跟踪的文件被修改了（红色）
- **Untracked**：新文件，Git 还没开始跟踪它
- **staged**：已暂存，准备下次提交（绿色）

### 1.5.2. 查看具体改了什么

```bash
# 查看工作区中所有文件的改动内容
git diff

# 查看某个特定文件的改动
git diff main.py

# 查看已暂存但还未提交的改动
git diff --staged
```

`git diff` 的输出中：
- 红色行（前面有 `-` 号）表示被删除的内容
- 绿色行（前面有 `+` 号）表示被新增的内容

### 1.5.3. 暂存文件（git add）

```bash
# 暂存指定文件（把文件放进"待发货清单"）
git add main.py

# 暂存所有改动（包括修改和新文件）
git add .

# 暂存指定类型的文件
git add *.py

# 暂存指定目录下的所有文件
git add src/
```

> **小提示**：`git add .` 中的 `.` 代表当前目录，这是最常用的暂存所有文件的方式。

### 1.5.4. 提交改动（git commit）

```bash
# 提交暂存区的内容到本地仓库。双引号中的内容是对当前变更内容的概述和总结
git commit -m "feat: 添加用户登录功能"

# 提交并附带详细描述（用多行）
git commit -m "feat: 添加用户登录功能" -m "实现了用户名密码登录
- 添加了登录表单
- 添加了密码验证逻辑"
```

`-m` 参数后面跟的是**提交信息**，应该简明扼要地描述这次提交做了什么。好的提交信息让别人（包括未来的你）一看就知道改了什么。

### 1.5.5. 查看提交历史

提交历史也叫提交日志。

```bash
# 查看完整的提交历史
git log

# 简洁模式：每行一个提交，显示简短的提交哈希
git log --oneline

# 图形化显示分支历史（推荐！）
git log --graph --oneline --all

# 查看某个文件的修改历史
git log -- main.py

# 查看某次提交具体改了什么
git show <提交哈希值>
```

> 下面的内容是一个 log 历史信息，`commit` 后面的内容就是 提交哈希值。
> 
> ```
> commit 25a9d73a1c9f9fc8803928d4d545a27b7f43a517 (HEAD -> next)
> Author: CnPeng <893612134@qq.com>
> Date:   Thu Oct 2 10:52:10 2026 +0800
>
>    调整文档名称
>```

## 1.6. 分支管理

### 1.6.1. 查看分支

```bash
# 查看所有分支（当前分支前面有 * 号标记）
git branch

# 查看远程分支
git branch -r

# 查看所有分支（包括本地和远程）
git branch -a
```

### 1.6.2. 创建和切换分支

```bash
# 创建新的 dev 分支（但不切换）, dev 是自定义的分支名。
git branch dev

# 切换到指定分支, dev 是自定义的分支名。
git checkout dev

# 【推荐】创建分支并立即切换（一条命令搞定）
git switch -c dev

# 切换回主分支, main 是自定义的分支名。
git switch main
```

> **提示**：`git switch` 是 Git 2.23+ 的新命令，专门用于切换分支，比 `git checkout` 更直观。如果你用的是旧版本 Git，请用 `git checkout -b dev`。

### 1.6.3. 删除分支

```bash
# 删除已合并的分支（安全方式）,dev 是自定义的分支名。
git branch -d dev

# 强制删除分支（即使未合并也删除）, dev 是自定义的分支名。
git branch -D dev
```

### 1.6.4. 分支操作完整示例

```bash
# 1. 确保在主分支上
git switch main

# 2. 创建并切换到新功能分支
git switch -c dev

# 3. 在分支上做一些修改后进行提交
git add main.py
git commit -m "feat: 实现登录页面"

# 4. 切回主分支
git switch main

# 5. 删除已完成的分支
git branch -d dev
```

## 1.7. 合并分支

### 1.7.1. 基本合并

当你在功能分支上开发完成后，需要把改动合并回主分支：

```bash
# 1. 切换到目标分支（通常是 main）
git switch main

# 2. 将 dev 分支的变更内容合并到当前的 main 分支。
git merge dev
```

如果两个分支没有修改同一个文件的同一位置，Git 会**自动合并**，没有任何问题。

### 1.7.2. 合并策略

```bash
#  将 dev 分支的变更内容合并到当前的分支。
git merge dev

# 强制创建合并提交（即使可以快进也创建合并节点）。注意，通常不推荐强制合并。
git merge --no-ff dev
```

### 1.7.3. 取消合并

如果合并后发现有问题，想回到合并前的状态：

```bash
# 取消当前的合并操作（回到合并前的状态）
git merge --abort
```

## 1.8. 远程仓库操作

### 1.8.1. 查看远程仓库

```bash
# 查看已配置的远程仓库
git remote -v
```

输出示例：

```
origin  https://github.com/username/repo.git (fetch)
origin  https://github.com/username/repo.git (push)
```

### 1.8.2. 添加远程仓库

```bash
# 给当前仓库添加一个远程仓库（名称通常为 origin）。
# git remote add 是固定命令格式；origin 是自定义的远程仓库别名；https://…… 是具体的远程仓库地址
git remote add origin https://github.com/username/repo.git

# 如果有多个远程仓库,可以多次执行 add 命令
git remote add upstream https://github.com/other-user/repo.git
```

### 1.8.3. 拉取远程代码

```bash
# 拉取并合并远程分支的最新代码
git pull origin main

# 先下载远程更新（不合并）
git fetch origin

# 拉取后自动创建上游跟踪
git pull -u origin main
```

> **重要**：`git pull` 等同于 `git fetch` + `git merge`。先下载远程变更，再自动合并到你的工作区。

### 1.8.4. 推送代码到远程

```bash
# 首次推送（关联远程分支并推送）
git push -u origin main

# 后续推送（简化写法）
git push

# 推送到指定分支
git push origin dev

# 推送所有分支
git push --all
```

`-u` 参数（即 `--set-upstream`）的作用是：建立当前分支与远程分支的关联，之后就可以直接用 `git push` 而不需要写完整路径。


### 1.8.5. 克隆时自动关联远程

```bash
# git clone 会自动添加远程仓库并关联 main 分支
git clone https://github.com/username/repo.git
cd repo
# 此时可以直接 git push 和 git pull
```

## 1.9. 冲突解决

### 1.9.1. 什么是冲突？

当两个分支修改了**同一个文件的同一行附近内容**，Git 无法自动决定该保留哪个版本时，就会产生冲突。

### 1.9.2. 冲突示例

假设 `main` 分支和 `dev` 分支都修改了 `main.py` 的同一个函数：

```python
<<<<<<< HEAD
def login():
    print("main分支的版本")
=======
def login():
    print("feature分支的版本")
>>>>>>> dev
```

Git 用 `<<<<<<<`、`=======`、`>>>>>>>` 这三个标记来告诉你冲突位置：
- `<<<<<<< HEAD` 到 `=======` 之间：当前分支（main）的内容
- `=======` 到 `>>>>>>>` 之间：要合并进来的分支（dev）的内容

### 1.9.3. 解决冲突的步骤


```bash
# 1. 查看哪些文件有冲突
git status

# 2. 打开冲突文件，手动编辑：
#    - 删除冲突标记（<<<<<< ====== >>>>>>）
#    - 保留你认为正确的内容
#    - 也可以把两边的内容都保留

# 3. 标记冲突已解决（把文件加入暂存区）
git add main.py

# 4. 完成合并提交
git commit -m "merge: 解决登录功能的合并冲突"
```

### 1.9.4. 放弃合并

如果冲突太复杂不想解决了：

```bash
# 取消合并，回到合并前的状态
git merge --abort
```

## 1.10. 撤销与回退

### 1.10.1. 撤销暂存的文件

```bash
# 把文件从暂存区移回工作区（取消暂存）
git reset HEAD main.py

# 或者用新命令
git restore --staged main.py
```

### 1.10.2. 撤销工作区的修改

```bash
# 丢弃工作区中某个文件的未暂存修改（危险！修改将无法恢复）
git checkout -- main.py

# 或者用新命令
git restore main.py
```

### 1.10.3. 撤销提交

```bash
# 撤销最后一次提交，但保留修改在工作区（改完重新提交）
git reset --soft HEAD~1

# 撤销最后一次提交，并把修改放回暂存区
git reset HEAD~1

# 彻底撤销最后一次提交（丢弃所有修改，危险！）
git reset --hard HEAD~1
```

> **警告**：`--hard` 模式会永久删除所有未提交的修改，使用前务必确认！

### 1.10.4. 修改最后一次提交信息

```bash
# 修改最近一次提交的注释
git commit --amend -m "新的提交信息"

# 修改最近一次提交的内容（把刚才漏加的文件加进去）
git add missed_file.py
git commit --amend --no-edit
```

## 1.11. Git 忽略文件

### 1.11.1. 创建 .gitignore

有些文件不应该被提交到仓库（如编译产物、配置文件、依赖包等）。创建一个 `.gitignore` 文件来指定忽略规则：

```
# .gitignore 文件内容示例

# Python 编译产物
__pycache__/
*.pyc

# 虚拟环境
venv/
.env

# IDE 配置
.vscode/
.idea/

# 操作系统文件
.DS_Store
Thumbs.db

# 依赖包
node_modules/
```

### 1.11.2. 忽略规则说明

- `*.pyc`：忽略所有以 `.pyc` 结尾的文件
- `venv/`：忽略名为 venv 的目录
- `#` 开头：注释行，Git 会忽略

> **注意**：`.gitignore` 只能忽略**从未被跟踪的文件**。如果文件已经被 `git add` 过了，即使加到 `.gitignore` 也不会生效，需要先用 `git rm --cached 文件名` 取消跟踪。

## 1.12. 日常使用流程总结

### 1.12.1. 日常开发标准流程

```bash
# 1. 开工前，先拉取远程最新代码
git pull origin main

# 2. 如果有新功能要开发，创建一个分支
git switch -c feature/new-feature

# 3. 在分支上开发，定期提交
git add .
git commit -m "feat: 完成XX功能"

# 4. 开发完成，切回主分支
git switch main

# 5. 合并功能分支
git merge feature/new-feature

# 6. 推送合并结果到远程
git push origin main

# 7. 删除已合并的功能分支
git branch -d feature/new-feature
```

### 1.12.2. 命令速查表

| 操作 | 命令 |
|------|------|
| 初始化仓库 | `git init` |
| 克隆仓库 | `git clone <url>` |
| 查看状态 | `git status` |
| 查看改动 | `git diff` |
| 暂存文件 | `git add <文件>` 或 `git add .` |
| 提交 | `git commit -m "信息"` |
| 查看日志 | `git log --oneline --graph` |
| 创建分支 | `git branch <名称>` |
| 切换分支 | `git switch <名称>` |
| 创建+切换分支 | `git switch -c <名称>` |
| 删除分支 | `git branch -d <名称>` |
| 合并分支 | `git merge <分支名>` |
| 添加远程 | `git remote add origin <url>` |
| 推送代码 | `git push origin main` |
| 拉取代码 | `git pull origin main` |
| 撤销暂存 | `git reset HEAD <文件>` |
| 撤销修改 | `git restore <文件>` |
| 忽略文件 | 创建 `.gitignore` |

### 1.12.3. 新手常犯错误

1. **忘记 `git add` 就直接 `git commit`**：提交后发现文件没进去，原因是忘了暂存。解决：`git add <文件>` 后再提交。

2. **误删代码没备份**：用了 `git restore` 或 `git reset --hard` 后代码就没了。解决：养成频繁 `git commit` 的习惯，每次提交都是一个安全点。

3. **直接在 main 分支上开发**：应该先创建功能分支再开发。解决：形成习惯，新需求先 `git switch -c feature/xxx`。

4. **推送前没拉取最新代码**：可能导致远程有新的提交而产生冲突。解决：推送前先 `git pull`。

5. **提交信息写得含糊**：如 "update"、"fix" 这种信息毫无意义。解决：用有意义的描述，如 "fix: 修复登录时密码为空时的崩溃问题"。
