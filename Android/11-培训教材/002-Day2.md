## 1.1. 四大组件

[官网：应用基础知识](https://developer.android.google.cn/guide/components/fundamentals?hl=zh-cn#Components)

Android 的四大组件是构成Android应用程序的基础，它们分别是：


* **Activity**（活动）：
   - Activity是应用程序的视觉呈现单元，代表一个具有用户界面的屏幕。它是用户与应用交互的主要方式。每个Activity都提供一个窗口，用于展示用户界面并接收用户输入。Activity之间通过Intent进行通信，可以启动新的Activity或传递数据。

* **Service**（服务）：
   - Service是一种在后台长时间运行且没有用户界面的应用组件。它用于执行长时间运行的操作，如下载、播放音乐、同步数据等，即使当应用被最小化或用户切换到其他应用时，服务仍可继续运行。

* **BroadcastReceiver**（广播接收器）：
   - BroadcastReceiver用于接收并响应系统或应用间的广播消息。这些消息可以是系统事件（如电池低、网络状态改变）或其他应用发出的自定义事件。接收到广播后，BroadcastReceiver会执行简短的操作，如启动Activity或Service，或更新通知等。

* **ContentProvider**（内容提供者）：
   - ContentProvider用于在不同应用间共享数据。它提供了一种标准的接口，使得一个应用可以访问另一个应用的数据，如访问联系人、图片库等。这为应用间的数据共享提供了一种安全且统一的方式，保证了数据的隐私性和安全性。

这四大组件是 Android 应用开发的核心，它们的设计旨在支持组件的重用、低耦合以及灵活的系统集成，共同构成了 Android 应用的基本架构。开发者需要在应用的`AndroidManifest.xml` 文件中声明使用的所有四大组件，以便系统能够识别和管理它们。

`android:exported `属性是在 Android 12（API 级别 31）及更高版本中引入的新属性。它决定了**其他应用是否能够启动这个 Activity**。

当 `android:exported` 设置为 `false` 时，意味着这个 Activity 只能被应用内部的其他组件（如其他 Activity、Service、BroadcastReceiver 等）启动，而不能[被其他应用或系统的隐式 Intent 启动](https://developer.android.google.cn/training/basics/intents/filters?hl=zh-cn)。

这有助于增强应用的安全性，因为它限制了哪些组件可以启动特定的 Activity。

```java
package cn.peng.stu4teach;

import android.content.Intent;
import android.os.Bundle;
import android.util.Log;
import android.view.View;
import android.widget.TextView;

import androidx.activity.result.ActivityResult;
import androidx.activity.result.ActivityResultCallback;
import androidx.activity.result.ActivityResultLauncher;
import androidx.activity.result.contract.ActivityResultContracts;
import androidx.appcompat.app.AppCompatActivity;

/**
 * 首页Activity
 */
public class MainActivity extends AppCompatActivity {
    private ActivityResultLauncher<Intent> mActivityLauncher;
    private TextView                       mTv;

    @Override
    protected void onCreate (Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        // 获取组件对象
        mTv = (TextView) findViewById(R.id.tv_main);
        initActivityLauncher();
        initClickListener();
    }

    /**
     * 初始化启动器，在其中读取返回的数据
     */
    private void initActivityLauncher () {
        mActivityLauncher = registerForActivityResult(new ActivityResultContracts.StartActivityForResult(),
                new ActivityResultCallback<ActivityResult>() {
                    @Override
                    public void onActivityResult (ActivityResult result) {
                        Log.d(getClass().getSimpleName(), "onActivityResult|" + result);
                        // 排除异常情况：result 为空；data 为空；resultCode 非法
                        if (result == null || null == result.getData() || result.getResultCode() != RESULT_OK) {
                            return;
                        }

                        // 读取数据并使用
                        Intent reData = result.getData();
                        String resultStr = reData.getStringExtra("ReData");
                        mTv.setText(resultStr);
                    }
                });
    }

    private void initClickListener () {
        mTv.setOnClickListener(new View.OnClickListener() {
            @Override
            public void onClick (View pView) {
                // 组织intent并携带数据跳转
                Intent intent = new Intent(pView.getContext(), TempActivity.class);
                intent.putExtra("StrData", "从Main传入的数据");
                mActivityLauncher.launch(intent);
            }
        });
    }
}
```

#### 1.1.1.4. intent 和 intent filter

[intent 和 intent 过滤器](https://developer.android.google.cn/guide/components/intents-filters?hl=zh-cn)

##### 1.1.1.4.1. 基础介绍

Intent 可以为“显式”，以便启动特定 Activity 实例；也可为“隐式”，以便启动任何可以处理预期操作（例如“拍摄照片”）的组件。

"显式" Intent 会指定要启动的 Activity 名称；“隐式”Intent 仅指定 Action。


##### 1.1.1.4.2. 常用intent

* [打开摄像头](https://developer.android.google.cn/guide/components/intents-common?hl=zh-cn#Camera)
* [拨打电话](https://developer.android.google.cn/guide/components/intents-common?hl=zh-cn#DialPhone)
* [打开设置页面](https://developer.android.google.cn/guide/components/intents-common?hl=zh-cn#Settings)

##### 1.1.1.4.3. 注意事项

**在使用隐式 Intent 启动 Activity 时**，尽管许多 intent 都可以由设备上安装的其他应用（例如“电话”“电子邮件”或“日历”应用）成功处理，但您的应用应该**做好准备，以便妥善应对没有 activity 可处理您应用的 intent 的情况。**每次调用 intent 时，都做好捕获 `ActivityNotFoundException` 的准备，如果没有其他 activity 可处理您应用的 intent，就会出现此异常：

```java
try {
    startActivity(intent);
} catch (ActivityNotFoundException e) {
    // Define what your app should do if no activity can handle the intent.
}
```

```java
package cn.peng.stu4teach;

import android.content.BroadcastReceiver;
import android.content.Context;
import android.content.Intent;
import android.content.IntentFilter;
import android.os.Bundle;
import android.os.PersistableBundle;
import android.service.restrictions.RestrictionsReceiver;
import android.util.Log;
import android.view.View;
import android.widget.TextView;

import androidx.activity.result.ActivityResult;
import androidx.activity.result.ActivityResultCallback;
import androidx.activity.result.ActivityResultLauncher;
import androidx.activity.result.contract.ActivityResultContracts;
import androidx.annotation.Nullable;
import androidx.appcompat.app.AppCompatActivity;
import androidx.localbroadcastmanager.content.LocalBroadcastManager;

/**
 * 首页Activity
 */
public class MainActivity extends AppCompatActivity {
    private ActivityResultLauncher<Intent> mActivityLauncher;
    private TextView                       mTv;
    private BroadcastReceiver mBroadcastReceiver;

    @Override
    protected void onCreate (Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        // 获取组件对象
        mTv = (TextView) findViewById(R.id.tv_main);
        initClickListener();
        initBroadcastReceiver();
    }

    private void initBroadcastReceiver () {
        IntentFilter filter = new IntentFilter();
        filter.addAction(TempActivity.ACTION_TEMP);
        mBroadcastReceiver = new BroadcastReceiver() {
            @Override
            public void onReceive (Context pContext, Intent pIntent) {
                if (null == pIntent) {
                    return;
                }

                String strFromBroadcast = pIntent.getStringExtra(TempActivity.KEY_DATA_FROM_BROADCAST);
                mTv.setText(strFromBroadcast);
            }
        };

        LocalBroadcastManager.getInstance(this).registerReceiver(mBroadcastReceiver, filter);
    }

    @Override
    protected void onDestroy () {
        LocalBroadcastManager.getInstance(this).unregisterReceiver(mBroadcastReceiver);
        super.onDestroy();
    }

    private void initClickListener () {
        mTv.setOnClickListener(new View.OnClickListener() {
            @Override
            public void onClick (View pView) {
                // 组织intent并携带数据跳转
                Intent intent = new Intent(pView.getContext(), TempActivity.class);
                intent.putExtra("StrData", "从Main传入的数据");
                startActivityForResult(intent,666);
            }
        });
    }
}
```

#### 1.1.3.4. 全局广播和本地广播对比（了解）

`LocalBroadcastManager.getInstance(pView.getContext()).sendBroadcast(intent);` 和 `context.sendBroadcast(intent);` 都是用来发送广播，但它们之间有重要的区别：

* **作用范围不同**:

   - `LocalBroadcastManager.getInstance(pView.getContext()).sendBroadcast(intent);`
     这个方法是通过 `LocalBroadcastManager` 发送广播，它仅限于应用程序内部。这意味着广播不会离开你的应用，只能被同一个应用内的其他组件接收。这对于敏感信息的传递更为安全，同时由于广播只在本地传播，因此效率更高。

   - `context.sendBroadcast(intent);`
     使用这个方法发送的是全局广播，它可以被设备上任何对这个广播感兴趣的注册了相应 `BroadcastReceiver` 的应用接收。这意味着广播不仅限于你的应用内，还可以跨应用边界，适用于需要多个应用间通信的场景。

* **性能和安全性**:

   - `LocalBroadcastManager` 由于其广播局限在应用内，因此更安全，减少了潜在的安全风险，同时因为不必经过系统广播机制处理，效率更高。

   - 全局广播涉及到系统级的处理，会有更多的开销，且可能涉及外部应用，存在一定的安全风险，特别是当你广播包含敏感信息时。

总结来说，如果你的应用内组件需要相互通信，并且不希望这些消息暴露给其他应用，`LocalBroadcastManager` 是更好的选择。而当你需要与其他应用共享信息或需要一个系统级的事件通知时，则应使用全局广播。

##### 1.3.1.2.2. 注意事项-setMovementMethod()

> 了解即可

在 Android 中，当你想要使 TextView 中的某些文本具有点击效果时，通常会使用`ClickSpan`或其子类（如自定义的`ClickableSpan`）。但是，仅设置这些Span并不足以使TextView识别并处理点击事件。这就涉及到`setMovementMethod()`方法的使用。

`setMovementMethod(LinkMovementMethod.getInstance())`的作用是为TextView指定一个MovementMethod，这个MovementMethod负责处理文本视图中的触摸事件。默认情况下，TextView使用的是`ScrollingMovementMethod`，它主要用于处理文本滚动。而`LinkMovementMethod`是专门设计来处理链接点击的，它能识别到`ClickableSpan`并触发相关的点击事件。

当TextView中有`ClickableSpan`时，如果不调用`setMovementMethod(LinkMovementMethod.getInstance())`，点击事件将不会被触发，因为TextView不知道该如何处理这些Span中的点击逻辑。通过设置为`LinkMovementMethod`，TextView就能识别并委托给`ClickableSpan`处理点击动作，从而实现点击文本时的交互效果，比如启动新活动、弹出对话框等。

因此，为了使带有`ClickableSpan`的TextView能够响应点击，调用`setMovementMethod(LinkMovementMethod.getInstance())`是必要的步骤。

##### 1.3.1.2.3. 注意事项-清除高亮背景

> 了解即可

在Android中，当你使用`ClickableSpan`并点击其中的文本时，默认情况下，被点击的文本周围会出现一个短暂的高亮背景色块，这个通常是系统默认的点击反馈效果。如果你想移除这个灰色背景块，可以通过设置TextView的`setHighlightColor`方法为透明色来实现。

下面是示例代码：

```java
TextView textView = findViewById(R.id.tv_main);
// 设置你的ClickableSpan以及其他属性
// ...

// 移除点击高亮背景
textView.setHighlightColor(Color.TRANSPARENT);
```

这段代码会使得在`TextView`中点击`ClickableSpan`时，不再出现灰色背景块。`Color.TRANSPARENT`是一个透明色值，这样就清除了点击时的高亮效果。

### 1.4.1. 简介

DataBinding 即数据绑定，能够让我们更便捷的将数据和视图进行绑定，简化数据呈现逻辑。

使用 DataBinding 后可以抛弃传统的 `findViewByID()`，不用过多的关注视图对象的类型，简化了数据呈现逻辑。DataBinding 比 ViewBinding 具有更强大的功能。
