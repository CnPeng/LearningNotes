安装过程很慢，速度为 kB 级别，大致需要十几到二十几分钟，甚至可能会直接报超时错误。原因：AndroidStudio 默认从境外的 maven 仓库拉取依赖项，所以慢。

#### 1.2.1.2. 解决gradle慢的问题

新建项目时默认使用最新版的可兼容 java 和 gradle , 如果本地没有最新版的 gradle 插件，在打开新建的项目时会执行下载。由于 gradle 服务器在境外，所以下载会很慢。

解决 gradle 下载慢的问题有如下两种方式：

##### 1.2.1.2.1. 方式1：手动下载并配置

* 先查看当前项目使用的 gradle 版本，


![](pics/20240615112145918_2063124245.png)

* 然后进入 [下载页面1](https://gradle.org/releases/?_gl=1*n3hz40*_gcl_au*MjI4Njk4ODM4LjE3MTU1ODM5OTQ.*_ga*MTUxOTQxMDQxMS4xNzE1NTgzOTk0*_ga_7W7NC6YNPT*MTcxODA2MjkxNy40LjEuMTcxODA2MjkxOC41OS4wLjA.) 或 [下载页面2](https://services.gradle.org/distributions/) 手动下载 gradle 文件。


* 下载完成，找到本地 gradle 的存储目录（ Mac 默认目录 `/Users/用户名/.gradle/wrapper/dists`）, 把文件放进去。

* 重新编译项目即可。


然后再从 AS 中切换为本地已有的 gradle 版本。


##### 1.2.1.2.2. 方式2：降级为低版本

* 先确认当前项目使用的 java 版本（参考 `指定java版本` 一节进行确定）, 如有必要可降级。

* 然后参考 [《过往的 Android Gradle 插件版本》](https://developer.android.google.cn/build/releases/past-releases?hl=zh-cn)，找到 java 版本与 gradle 的对应关系，

##### 1.2.1.2.3. 方式3：替换gradle下载源

[Gradle 官网 https://services.gradle.org/distributions/](https://services.gradle.org/distributions/) 提供了 Distribution 服务，但由于网络环境不同以及其他因素，从官方网站下载 Gradle 会比较慢。

为了解决 Gradle 下载过慢的问题，我们可以利用国内镜像站点来加速下载。以下是一些国内镜像站点提供的 Gradle 下载地址：

##### 1.2.1.3.1. 局部添加国内镜像

* 先关闭当前的下载：

* 添加阿里云镜像服务（务必添加到第一位）。


![](pics/20240609123052309_1684665624.png)


![](pics/20240609124558534_2022472093.png)


注意：AGP（Android Gradle Plugin）版本不同，配置方式略有差异。8.0及后续的新版中是在项目根目录的 `setting.gradle` 中配置，旧版是在项目根目录的 `build.gradle` 中配置。旧版的配置方式如下：

```groovy
allprojects {
    repositories {
        maven {
            url 'https://maven.aliyun.com/repository/public/'
        }
        mavenLocal()
        mavenCentral()
    }
}
```

##### 1.2.1.3.2. 全局修改镜像地址

> 待测试。原文：[CSDN《解决Gradle下载依赖速度慢的问题》](https://blog.csdn.net/interest_ing_/article/details/141502481)

在 `C:\Users\[用户编号]\.gradle` 目录下新建文件 `init.gradle` ，写入如下内容：

```groovy
allprojects{
    repositories {
        def MY_ALIYUN_REPOSITORY_URL = 'http://maven.aliyun.com/nexus/content/groups/public'
        def MY_ALIYUN_JCENTER_URL = 'http://maven.aliyun.com/nexus/content/repositories/jcenter'
        all { ArtifactRepository repo ->
            if(repo instanceof MavenArtifactRepository){
                def url = repo.url.toString()
                if (url.startsWith('https://repo1.maven.org/maven2')) {
                    project.logger.lifecycle "Repository ${repo.url} replaced by $MY_ALIYUN_REPOSITORY_URL."
                    remove repo
                }
                if (url.startsWith('https://jcenter.bintray.com/')) {
                    project.logger.lifecycle "Repository ${repo.url} replaced by $MY_ALIYUN_JCENTER_URL."
                    remove repo
                }
            }
        }
        maven {
            url MY_ALIYUN_REPOSITORY_URL
            url MY_ALIYUN_JCENTER_URL
        }
    }
}
```

##### 1.2.6.3.2. 使用adb 命令配对

> 需要先确保 adb 命令存在，且已经配置了环境变量。然后从手机端打开 `使用配对码配对设备` 的弹窗，并确保弹窗不被关闭。

如果通过图形界面一直无法配置成功，可以使用 adb 命令进行配对。

andorid 系统版本 大于10 时，依次在终端执行如下命令：

```bash
# 1、手机端选择 "使用配对码配对设备" 后，弹窗中呈现的 IP 地址和端口
adb pair 配对操作界面呈现的IP地址和端口

# 2、手机端无线调试界面中呈现的 IP 地址和端口号
adb connect 无线调试界面下的IP地址:端口
```

#### 1.3.2.2. 远程仓库操作

实际开发中，公司都会有自己的远程仓库，可能是使用 gitee、github , 也可能是基于开源库自行搭建。此处以 gitee 为例，需要先从 [gitee](https://gitee.com/) 注册用户。

命令 | 含义
---|---
`git clone 远程项目地址` | 将远程项目拉取到本地
`git remote -v` | 查看当前项目关联的远程分支
`git remote add 远程仓库别名 远程仓库地址` | 将本地项目与远程仓库进行关联
`git remote remove 远程仓库别名` | 将本地项目与远程仓库解除关联
`git pull 远程仓库别名 远程分支名` | 将远程仓库中的内容拉取到本地
`git push 远程仓库别名 远程分支名` | 将本地修改的代码推送到远程仓库中

使用 `git clone 远程项目地址` 将远端项目拉取到本地后，不需要再执行 `git remote add 远程仓库别名 远程仓库地址`。

一个本地项目可以关联多个远程仓库，直接使用 `git remote add 远程仓库别名 远程仓库地址` 关联即可。
